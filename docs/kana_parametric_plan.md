# P1-B: 仮名パラメトリック生成計画 v1

P1（ひらがな核心20字）を「Glyphs で人が描く」代わりに、**骨格をコードで定義しエンジンで肉付けする**方式。狙いは品質・再現性・検証容易性。
2026-08-10 確定。Grok 4.5 レビュー（審美・DSL・計測・工数の批判的検証）を反映済み。

## 0. 成功定義（正直に）

> **「描画の手作業を、レビュー可能なパラメータ手作業＋機械肉付けに置き換える。審美探索は人がやるが、探索空間と合否はコードが閉じる。」**

- 「人手ゼロ」は掲げない。骨格数値を決めるのは人間。差分は (1) 操作媒体が GUI でなく diff 可能な YAML (2) 検証が決定的・CI 可能 (3) motif 共有で字を横断する一貫性制約が効く、の3点
- 勝ち筋は核心20字ではなく**残り150字＋様式変更時の回収**。20字だけなら手描きの方が速い可能性を認める
- クリーンルーム維持: 参照書体はラスタ半透明の**位置合わせガイド表示のみ**。座標転記・トレース禁止（掟9）。校正はスカラー計測のみ
- 最終合否は外部盲検（`docs/blind_test.md`、UI/HUD 2面 2/3）。審美の最終判断から人間は外せない

## 1. 骨格 DSL（`engine/kana/skeletons/*.yaml`）

**正本は cubic ベジェ列**。通過点（Catmull-Rom）は編集補助ビューに格下げし、CI・黄金比較は cubic に対して行う（通過点方式は曲率制御が点移動の副作用になり、再現性の売りが消えるため）。

1字 = `elements[]`:

| フィールド | 内容 |
|---|---|
| `spine` | cubic ベジェ列（正本）。**節点数上限 ≤6/element をゲート化**（過学習防止） |
| `width` | **弧長 s∈[0,1]** の keyframe。**非単調可**（入口細→肩太→たまり急膨張→抜き急細）。ピーク型（gaussian/bias）指定可 |
| `ends` | `{entry, exit}` × テンプレID＋スカラー（角度°・深さUPM・asymmetry） |
| `joins` | 複画時のみ: 相手 element id・接合型（T/交差/重ね）・overlap UPM |
| `loop_closure` | ループ字のみ**必須**: `{overlap_upm, join_angle}` |
| `motif` | `curve_shi` / `loop_no` / `corner_ka` 等。**同一 motif は共有パラメータで縛る**（字ごと独立最適化の禁止） |

端物テンプレ（タグ名だけでなく幾何をテンプレとして定義する）:

| テンプレ | 用途 | 備考 |
|---|---|---|
| `karui_uchikomi` | 軽い打ち込み（斜め入り→徐々に立つ） | 入口角は DoD で管理 |
| `tome_maru` | 丸止め・たまり（涙滴） | 幅プロファイルの急膨張と連動 |
| `nuki` | 抜き（先細り。**抜きの向きが次画を指す**） | 筆脈の連続 |
| `sori` | そり | |
| `kado_tome` | 角止め（か・き・こ・さ・た・て・と） | **KANA_CURVE 一本主義の「ゴムホース仮名」防止** |
| `hane_kana` | はね（い・り系） | 漢字用 HANE と別物 |

ハイブリッド許容: 端物は将来 **手調整 UFO 部品**への差し替え可能な構造にする（「手の温度」がテンプレで出ない字への出口）。

## 2. エンジン拡張

1. `StrokeKind.KANA_CURVE`: cubic 列 → **弧長パラメータ化**サンプリング → 幅プロファイル → `variable_width_outline`（既存）
2. **肉付け前ゲート**: 最小曲率半径 ≥ k×半幅。違反は YAML 側を fail（エンジンが黙って補正しない）
3. **ループ字は明示リング生成が第一経路**（outer＋inner の2輪郭を直接生成）。自己交差 union 頼みにしない。union は複画接合専用
4. カウンター保護: 仮名では微小輪郭除去の面積床を漢字用（0.0035 UPM²比）のまま使わず、**「負面積＝穴」は除去禁止**フラグを必須化
5. **仮名は cubic を最後まで保持**。漢字用 `rdp_polyline` を仮名デフォルトにしない（節点ノイズ＝「安フォント感」の直撃）。再適合するなら曲率適応フィット（Hausdorff ≤1.0–1.5 UPM）を別ゲートで

## 3. 数値校正（帯は外れ値排除。「顔」は別レイヤ）

**帯だけで顔には近づかない**、を運用に明記する。計測は層別に導入:

| 層 | 指標 | 用途 | 導入 |
|---|---|---|---|
| L0 | 字面率・ink密度・重心(x,y)・線幅min/max・コントラスト | 大域外れ値排除 | スパイク8aから |
| L1 | **カウンター面積比・縦横比**（あ/の）、**サイドベアリングL/R**（固定文面の字間ギャップ） | ふところ崩壊・UI歩行 | 8cまでに必須 |
| L2 | 曲率ヒストグラム（κ p95）・幅弧長プロファイル相関 | ホースカーブ・太細リズム | 推奨（20字展開前） |
| 不採用 | 画素CNN類似度・骨格DTW | トレース誘導・説明困難 | — |

- 帯のソースは **伝統明朝クラスタ4書体**（源ノ・IPAex・しっぽり・Zen Old。**BIZ UD は除外**、UDは別トラック）中央値±許容。`fontdb/config/kana_targets.yaml` に extractor_version 付きで凍結（掟8）
- **自動調整の自由度は2つまで**: (1) 全体 stem スケール (2) 字面ボックス合わせ。それ以上の自動最適化は禁止（字ごと独立最適化は20字の一貫性を壊す）。(2) は YAML `em_fit`（完成輪郭の等方スケール＋`target_lsb`。`engine/kana/em_fit.py`）
- 大域パラメータは `kana_r1` として product_r1 と分離して凍結（掟16）
- 計測経路は既存 T7（一時OTF→freetype）で同一物差し（掟4）

## 4. 反復ループ（決定的・CI可能）

内部品質装置の詳細は `docs/kana_review_loop_plan.md` v2（B=数値ゲート必須、C=Gemini観察は任意）。

```
骨格YAML編集 → regen → kana_gate v2（接合・突き抜け・方位等）
   → [任意] kana_render → Gemini観察JSON
   → 修正（YAMLのみ）→ 人間accept → proofs/golden/kana_* 凍結
盲検前: make_proofs（UI/HUD）→ S4（本ループの置き換えではない）
```

イテレーション削減装置（実装順）:
1. **骨格オーバーレイ可視化**: 参照4書体ラスタ半透明＋自作輪郭（ガイドのみ・トレース禁止）
2. **1パラメータ感度PNG**: stem±5%・entry角±5° 等を自動生成し「効くノブ」を先に知る
3. **motif ライブラリ**: 字YAMLは配置＋少数スカラーに縮退
4. **編集バジェット**: 1字あたり触ってよいスカラー ≤12。超過は DSL 設計不足のシグナル

## 5. 品質ゲートと DoD（数値）

共通（全段階）: pathops self-intersect=0／期待 contour・**hole 数**一致／同一 SHA 入力 → 輪郭ハッシュ一致（再現性）。

| 段 | 字 | 読める(G1) | 帯に入る(G2) | 見られる(G3) |
|---|---|---|---|---|
| 8a | し | 単一contour・認識可 | 字面率∈参照中央±8%・stem max∈±12%・重心Y∈±3%EM | 「ししし」混植でホース感なし＋κ p95 ≤ 参照×1.3 |
| 8a' | い・と（審美並走） | 同上 | 同上 | **UI歩行の早期検知**（縦要素・字面の据わり） |

## 6. 工数と撤退ライン

| 項目 | 楽観 | 中央 | 悲観 |
|---|---|---|---|
| P1-B 核心20字 合計 | 170h | **305h** | 520h |

従来手設計 M1（150–300h）と中央値で同等〜やや上。回収は残り150字とウェイト展開で行う。

**撤退ライン（掟20と同型）**: し＋つの G3 到達に **40h 超**かかったら端物テンプレ不足とみなし、**Glyphs で核4字（し・つ・の・あ）を手描き → パラメータ逆計測**のハイブリッドへ切り替える。字単位の方式A退避も常時許容。

## 7. 習作化リスク Top3 と緩和（レッドチーム指摘の採用）

1. **端物と筆脈の「手の温度」がテンプレ化** → 端物を UFO 部品差し替え可能に。入口角・抜き向き（次画を指す）を DoD 管理
2. **複画・ループの呼応を大域帯が最適化しない** → motif 共有制約＋カウンター形状ゲート必須。字ごと損失でなく**セット損失**（20字の重心分散・motif一致）
3. **オフセット肉付け＋polyline 再適合が「張り」を殺す** → 仮名は cubic 正本を最後まで保持

## 8. PLAN との整合

- PLAN §0「仮名は手設計必須」の解釈: 「手設計＝人間による設計判断」。P1 の DoD（OTF で組める＋組見本凍結）は不変
- M1 見積は 170–520h（中央305h）に更新。スパイク8a/8b の実測で再見積もり
- 盲検不合格 → 掟20 どおり骨格 YAML（または方式Aハイブリッド）に回帰
