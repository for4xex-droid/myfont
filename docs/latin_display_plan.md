## 1. 4様式の定義（案）

タイポアートでは、並べたときに4様式の区別がつくことが最低条件になる。そのため、各様式を**計測できるスカラー**で定義する。見た目の印象語は補足に留める。

「モダン」は活字史では Didone（ボドニ系）を指すが、それだと「シック」と区別できない。D0 で **モダン＝幾何サンセリフ、シック＝ディドン** に確定した。

| 様式 | 骨格の型 | コントラスト比（太/細） | 応力軸 | 端物 | 比例 | 角 |
|---|---|---:|---|---|---|---|
| モダン（幾何サンセリフ） | 円・直線・正三角 | 1.0–1.15 | なし | 平切り | 幾何比例（O≈正円） | 鋭角の頂点（A M N V W） |
| クラシック（ローマン大文字） | 碑文型の古典比例 | 2.0–2.8 | 斜め −15°〜−25° | ブラケット付きセリフ | 古典比例（O・C・D・G・Q 広、E・F・L・S・B・P 半正方） | 頂点を少し切る |
| シック（ディドン） | 垂直軸の対称形 | 8–12 | 垂直 0° | ヘアラインセリフ（ブラケットなし）、ボール端（J 2 3 5 6 9） | コンデンス（O の幅/高 0.62–0.78） | 鋭い |
| ポップ（丸ゴシック系ヘビー） | モダンの骨格を太らせた形 | 1.0–1.1 | なし | 丸 | やや広い | 角丸 r = 0.3–0.5×ステム |

上の数値の帯は草案である。2026-09-30 に、パイロットの実測で分離を凍結した。ゲートが使うのは `engine/src/engine/latin/targets/separation.yaml` で、シックのコントラスト 7.25 と O の幅/高さ 0.80 もこの実測のままである。

共通の設計値（仕様項目ではなく設計パラメータ。様式 snapshot に入れる）:

- UPM 1000、キャップハイト 700、ベースライン 0
- オーバーシュート: 丸 1.5–2%H、尖り頂点 2–3%H
- ステム（Regular 相当）: モダン ≈0.13H、クラシック縦 ≈0.14H、シック縦 ≈0.16H、ポップ ≈0.22H
- サンセリフの横画は縦画の 0.88–0.93 倍（光学補正）
- 数字はライニング（大文字と同じ高さ）。オールドスタイル数字は作らない
- `/` は字高いっぱいに取り、角度は様式ごとに決める（モダン 60°前後、シック 70°前後）

ポップの「跳ね」（字ごとのベースラインずれ・回転）は実験扱い。既定では入れず、L2 で入り／なしの2案を比べる。

## 2. 生成方式（既存エンジンの流用）

パラダイムは日本語と同じ「骨格 YAML＋ペンモデルで肉付け＋union」。Knuth の方式にならい、**骨格（字の構造）とパラメータ（様式）を分けて持つ**。

```
glyph 骨格 YAML（37字 × 構造の型）
   └─ 様式 snapshot（ペン・端物・比例・補正）
        → 肉付け → 端物テンプレ → pathops union → cubic フィット
        → UFO（様式ごと）→ ゲート → 組見本
```

### 2.1 骨格

書き方の正本は `docs/latin_impl_plan.md` §4.1。ここには方針だけを書く。

- 仮名のローダは一般化しない。ラテン用ローダを `engine/src/engine/latin/` に新設する（仮名コードは変えない）
- 1字 = `strokes[]`。各 stroke は節点列（`knots`。型は smooth / corner / line）で書き、Hobby 展開で cubic 列にする。制御点は書かない。ほかに `ends`、`joins`
- 様式で構造が変わる字（A の頂点、G のひげ、J の降り、Q の尾、R の脚、M の開き、1 の旗、4 の開閉）は、字 YAML に `variants: {style: ...}` を持たせる。variant は構造の差に限る。太さを変える用途には使わない
- 字幅は骨格に書かない。様式 YAML の `proportions`（字ごとの幅係数）で決める

### 2.2 ペンモデル（新規。ここが本体）

| ペン | 式 | 使う様式 |
|---|---|---|
| `mono` | 半幅一定 | モダン・ポップ |
| `nib(θ, c)` | 半幅 = w_min + (w_max − w_min)·\|sin(φ − θ)\|（φ = 接線角） | クラシック（θ ≈ 30°）・シック（θ = 0°、c 大） |
| `round_join` | mono の角に円弧ジョインを入れる | ポップ |

1本の `nib` 式でクラシックとシックを出すため、2様式の差はパラメータの差に収まる。既存の `variable_width_outline` は半幅列を受け取るので、ペンは半幅列を作る関数として足す。

### 2.3 端物テンプレ

`flat`、`round`、`serif_bracketed(len, bracket_r)`、`serif_hairline(len)`、`ball(r)`、`spur`。端物はペンで掃かず、閉じた塗りの部品として union する（詳細は実装計画 §2.5）。`join_solver` は変更しない。

### 2.4 曲線

タイポアートは大きなサイズで使うため、折れ線は見える。**漢字用の `rdp_polyline` は使わない**。仮名で入れた `cubic_fit`（Hausdorff ゲート付き）を既定にし、次の条件をゲートにする。

- 丸い部分の x/y 極値にオンカーブ点がある
- 輪郭あたりの節点上限は、様式 YAML の `curve.max_anchors_per_contour`（初期値 12）
- ゲートを超えたら fail にする。黙って折れ線に戻さない

### 2.5 光学補正（機械で入れる分）

オーバーシュート、股の細め（V W M N の内角。ディドン以外）、丸字の幅増し、サンセリフ横画の細め、O の上下を左右より細く（サンセリフでも 0.95 程度）。どれも snapshot のスカラーにする。字ごとの自由スカラーは 12 まで（実装計画 §4.1）。

## 3. 参照と権利（掟9・掟12）

- 参照は OFL などオープンライセンスの書体に限る。取るのはスカラーだけ（コントラスト・応力角・比例・オーバーシュート）。輪郭のトレースや座標の転記はしない
- 候補（**ライセンス条文の確認前なので未採用**）: 幾何サンセリフ＝Jost・Poppins、ローマン＝Cinzel・EB Garamond、ディドン＝Playfair Display・Bodoni Moda、丸ゴシック＝Nunito・Fredoka
- 追加は `fontdb/config/corpus_latin.yaml` のエントリで、ライセンス確認を完了条件にする（掟12）
- 独自性の確認は既存の IoU＋レイ距離（`rights_distance.py`）で行う。参照同士の距離を基準線にし、「寄りすぎ」だけを見る。合否や自動調整の目的関数にはしない
- 碑文のローマン大文字は様式として公有だが、デジタル書体は公有ではない。比例は文献の比率（正方形・半正方形の区分）から取る

## 4. ゲート

### 4.1 字ごと（自動・pytest）

- 期待輪郭数と穴の数が一致する（穴あり: A B D O P Q R 0 4 6 8 9。モダンの 4 が開いた形なら 4 を外す）
- 自己交差 0（pathops）
- キャップハイト・ベースラインのオーバーシュートが帯内
- §2.4 の曲線ゲート
- 同じ入力なら輪郭ハッシュが一致する（再現性）

### 4.2 セット（自動）

- 縦ステムの中央値がセット内 ±5%
- 計測したコントラスト比と応力角が §1 の帯に入る（O と H で測る）
- **様式分離**: 4様式を（コントラスト、応力角、端物の種類、角丸半径、O の幅/高）の空間に置き、どの2様式も距離が閾値を超える。閾値は L2 の実測で決め、凍結する（掟8）

### 4.3 引き渡し（`scripts/generated_face_spec.py` ＋ `ship_gate.py`）

- 仕様の未決定が残っていれば書き出さない（実装済み）
- cmap が39字ちょうど。収録外の字があれば fail
- name テーブルはファミリー名の決定後の命名だけを使う

### 4.4 目視・盲検

固定文面（39字だけで組める）を使う。

- `ABCDEFGHIJKLMNOPQRSTUVWXYZ` / `0123456789` / `2026/09/29` / `NEW/OPEN` / `SALE 50` / `TOKYO/PARIS/2026`
- 空白の字幅を見るため、`SALE 50` と `NEW OPEN` は空白入りで組む
- 48 / 120 / 300px。タイポアートの使い方として、字詰め −5%、2〜3行の積み、白抜き、輪郭線のみ、の4条件でも組む
- 黄金は様式ごとにバージョン付きで凍結する（掟18）

盲検は評価者3名。

1. 様式当て: 4枚を4ラベルに対応させる。各様式で 2/3 以上が正解
2. 使えるか: 様式ごとに 2/3 以上が「使える」
3. 既存の有名書体に見えるか: 記録だけ（合否にしない）

工数の正本は `docs/latin_impl_plan.md` §7。1ウェイト・4様式（工程 1–10、13、R）の足し算は **234–405h**。この表の L 番号は制作の粗い順番で、時間の見積には使わない。

L1 と L2 は 2026-09-30 にパイロットとして到達した。比較シートは `proofs/latin/pilot_sheet.png`。作者は4様式を区別でき、分離閾値は凍結済み。次は L3 のモダン。B の接合の切れ目は残る。L6 の引き渡しは、仕様の未決定が残るあいだ出さない。

順番の理由: モダンは `mono` ペンと直線・円だけで基盤を検証できる。ポップはその骨格を再利用できる。シックとクラシックは `nib` ペンを共有し、クラシックが比例と端物で最も難しい。

### 撤退ライン

- L1 で `nib` ペンの O が §2.4 のゲートを 16h 以内に満たせない → その様式の Regular を Glyphs で手描きし、エンジンはゲート・字間・書き出しだけに使う（実装計画 §8 と同じ）
- L2 で4様式が分離しない → 字形を足す前に §1 の定義を見直す
- 1様式の37字が見積の悲観値を超えた → その様式を後回しにし、残りを先に閉じる

## 6. やらないこと

| やらない | 理由 |
|---|---|
| 小文字・約物・日本語・異体字 | 仕様で未決定 |
| 未決定項目（太さ・命名）を仮置きで書き出す | 仕様 §2 |
| 参照書体のトレース・座標コピー | 掟9 |
| 生成モデル（GAN・拡散）で出荷輪郭を作る | クリーンルームと説明可能性 |
| 画素類似度を合否にする | 既存方針 |
| 漢字用 `rdp_polyline` を既定にする | 大サイズで折れが見える |
| 字ごとの独立最適化 | セットの一貫性が壊れる |
